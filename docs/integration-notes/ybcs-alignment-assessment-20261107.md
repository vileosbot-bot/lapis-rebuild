# ybcs → lapis-rebuild 对接评估

文档类型：技术对接评审定稿
评审范围：游戏逆向工程、数据迁移、战斗逻辑与 Web 重构
主线仓库：lapis-rebuild
辅助素材：ybcs-offline（Lapis Legacy Offline）
总体决策：方案 A，以 lapis-rebuild 为唯一开发主线

## 一、结论

结论：可行，建议采用方案 A。

ybcs-offline 与 lapis-rebuild 使用同一份 NeoDark.exe 2.2 客户端，实测 SHA-256 一致：

c1be05eb2977a8aae8cbe8b716bc1e3957263edde8187d5269d554b327f13cbd

这意味着两套工程具有共同的客户端基线，可以围绕同一套游戏数据与行为进行交叉分析。

两者的定位应当明确区分：

- lapis-rebuild：唯一主线，负责游戏架构、解析器、运行时、战斗系统和最终 Web/PWA 产品。
- ybcs-offline：第二个独立重构实现，提供游戏世界数据、任务规则、NPC 服务、战斗公式和真人试玩行为语料。

对接原则：只补充 lapis-rebuild Backlog 中明确存在的缺口，不重复建设已有能力。

当前 lapis-rebuild 已完成 M0–M8.0，剑士、巫师双职业的 20 阶段可玩，SPR、ANI、SGR、MMF、Tip、Set.lib、Quest.lib 解析器已经验证。

因此，本次对接不应重新研究已经验证的格式解析层，而应将精力集中在游戏内容和规则层。

核心决策

不迁移整个 ybcs 工程，不另起独立重构分支。

优先补齐第一章完整冒险链所需的世界内容。

其次交叉验证伤害公式，避免两套战斗规则长期分叉。

最后挖掘真人试玩日志，建立怪物与 AI 程序的绑定关系。

所有迁移内容均采用 JSON 数据 + TypeScript policy 的方式接入现有主线。

建议执行顺序：评估定稿 → 世界内容优先 → 战斗交叉验证 → 日志语料挖掘。

当前第一步是完成本评估定稿。下一步由 lapis-rebuild 主线维护者负责启动世界内容对照与第一章数据接入，ybcs 侧提供相应素材和证据。

### 2.3 证据等级

本次对接统一采用以下证据标准：

ybcs 来源的证据等级：第二个独立重构实现 + 真人试玩行为语料。

具体规则：

ybcs 中已有的实现、配置和运行结果均不能标记为 VERIFIED。

本次评估不重新裁定任何已经验证的解析器结论。

### 3.2 S1：场景与战斗遭遇绑定

目标：建立场景、事件与战斗场景之间的对应关系。

ybcs 的世界目录和 1–10 章遭遇部署可作为 lapis-rebuild 当前场景事件系统的补充材料。

建议建立独立的遭遇对照表，至少记录：

所属地图。

场景或事件标识。

对应战斗场景。

ybcs 来源。

是否存在冲突。

关键约束：

lapis-rebuild 已验证的 S1 路径具有优先权。

如果 ybcs 的绑定与现有路径不同，先记录差异，不能直接覆盖。

待核实方法：使用同一客户端基线，逐项对照地图、事件触发条件和战斗入口，并通过实际运行验证。

### 3.3 S2：怪物与 AI 程序绑定

目标：建立怪物遭遇与 AI 程序之间的映射关系。

ybcs 的 AI 行为模块和战斗 profile 提供候选映射，walkman 实玩会话日志提供真人操作过程中的行为语料。

建议以日志为主要分析入口：

识别日志中的遭遇开始和结束。

提取遭遇期间出现的 6A 69 程序下发记录。

关联对应的怪物和战斗 profile。

记录程序 ID、遭遇序列及上下文。

对每条记录计算并登记来源文件 SHA-256。

写入 manifests/enemy-ai-binding.json。

关键约束：

不能仅凭 AI 模块中的配置关系认定某个怪物必然使用某条 AI。

必须保留日志证据和来源哈希。

待核实方法：抽取代表性遭遇，对照日志中的程序下发顺序与实际战斗行为，确认映射是否成立。

### 3.4 S3：物理与魔法伤害公式

目标：将 ybcs 的战斗公式作为第二套独立实现，与 lapis-rebuild S19 balance 进行交叉验证。

ybcs 的 game_domain.py 包含完整的物理与魔法战斗公式实现，可用于发现 lapis 当前平衡模型中的缺失项或差异。

建议采用统一输入：

相同 .atr 数据。

相同攻击者与防御者属性。

相同装备与状态。

相同技能及攻击类型。

相同战斗条件。

逐项比较：

物理伤害计算。

魔法伤害计算。

攻防属性参与方式。

技能修正。

状态效果修正。

最终伤害与取整结果。

输出公式差异表，明确记录两套实现的计算结果、差异原因、证据来源和裁定结果。

关键约束：

不能直接将 game_domain.py 替换进 lapis-rebuild。

最终以交叉验证后的统一规则为准，保留差异记录。

待核实方法：使用相同输入数据执行两套公式，对比中间计算值和最终伤害值。

### 3.5 S4：任务、招募、NPC 服务与传送

目标：补齐游戏世界中的任务推进与 NPC 服务规则。

ybcs 对应素材包括：

关键约束：

SMF object_id 不得直接等同于 NPCScript blockId 或 Quest NAME。

必须先核实各自语义，再建立显式映射。

待核实方法：结合客户端解析结果、NPC 对话行为和任务推进过程，逐项确认对象关联与判定条件。
